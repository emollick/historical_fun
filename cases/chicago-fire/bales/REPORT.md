## API pattern that works
`https://openlibrary.org/search/inside.json?q=<urlencoded query>&limit=10`
- Semantics (established by probes q0001–q0017, see query_log.tsv): every quoted phrase and every bare word is a **required** (AND) clause;
  `OR` is just the word "or"; `|` yields 0 hits; a trailing `*` works as a prefix (q0013). `limit` = number of *books* returned (max 100), not fragments.
- Each book hit carries `highlight.text`: at most **5 fragments**, each ~100 characters, centred on the matched phrase (Lucene fast-vector highlighter behaviour),
  boundaries snapped to word/punctuation. Fragments are ranked by number of highlighted spans, ties in **document order** (front matter → chapters → appendices → notes).
  So a 5-phrase query returns one fragment per phrase if each phrase occurs once, and a phrase occurring N times returns its first N occurrences in book order.
- `fields.page_num` is always `[[358]]` (leaf count) — no per-hit page numbers. Page numbers below come only from running heads, TOC lines, figure captions and footnote numbers visible inside fragments.
- A single common phrase may leave Bales outside the top hits (e.g. `"12th witness"`: 38 books, Bales not in top 10); adding a phrase unique to the book
  (I use `"loosened them as quick as I could"`, which occurs once, in Sullivan's testimony) forces the book to the top at the cost of one fragment slot.
- Text recovery is by **chaining**: take the last 4 words of a known fragment, query them (batched 4 phrases per query), receive the next ~100-char window
  centred on them, i.e. ~40 new characters per phrase. Driver: `chain.py` (state in `chains.json`); every request is logged in `query_log.tsv`, raw JSON in `raw/qNNNN.json`.
- The API is flaky: intermittent "connection reset by peer" and HTTP 500 (both retried with backoff). No 429 seen at ~1 request/s.

### Exact API pattern that worked
`GET https://openlibrary.org/search/inside.json?q=%22phrase%20one%22%20%22phrase%20two%22%20...&limit=10` (browser User-Agent; ~1 req/s; retry on 500/502/503/504/429 and on TCP resets, which are frequent through the proxy — roughly one in eight requests needed a retry, none were permanent).
Response: `hits.hits[]` (one per book) → `fields.identifier[0]=="greatchicagofire0000bale"`, `highlight.text[]` = up to 5 fragments with `{{{...}}}` markers. Best practice found: 4 quoted 6-word phrases per query (one fragment each), plus the unique anchor phrase `"loosened them as quick as I could"` whenever a query has fewer than 3 phrases. No way was found to raise the 5-fragment cap, to get page numbers, to exclude the note citations, or to use OR/NOT.
