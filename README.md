# Historical Mysteries

Eighteen historical mysteries examined from the original documents, each ending in a verdict with a
stated confidence, the strongest opposing case answered by name, what would overturn the verdict, and
the code and data behind it. The results are research arguments, not solved mysteries: each reproduces
and extends an argument specialists had already made, several turn up overlooked details, and the
headline conclusions are readings of the evidence. This repository holds the website and the complete
working folder of every case.

Site: https://historical-mysteries.netlify.app

## Scoreboard

Evidence labels: Strong (the evidence leaves little room for another answer); Probable (the evidence clearly favours one answer over all the others, but does not prove it); Leading candidate (several answers remain possible and are put in order); Unsettled (no answer is clearly ahead of the others).

| [Hannibal's route over the Alps](cases/hannibal-alps/) | On the weights used here the Col du Clapier comes first at about 40 per cent, on condition that Polybius's Island lies between the Rhône and the Isère; the Col de la Traversette is second at about 30 and the Mont-Cenis third at about 15. | about 40% (20 to 60, the 5 to 95 per cent Monte-Carlo band) | Leading candidate | Agrees with the cautious verdict for the Clapier that Perrin reached in 1883, that Azan (1902) and Colin (1904) developed, that Walbank (1956), Proctor (1971), Lazenby (1978), Lancel (1995), Hunt (2017) and Hornblower (2024) repeated with the same caution, and that Kuhle and Kuhle defended against Mahaney in 2012, and agrees with them that the question remains undecided; shifts the Traversette from "the first direct evidence of the route", the words of Mahaney and colleagues in Archaeometry 2017 part II, with "solid evidence" in the press coverage of 2016, to a strong second whose physical case has not been tested |

## Layout

- `site/` is the website as deployed: `index.html` (the cover page, one table row per case), one folder
  per case with the case page (`index.html`, which ends with a "What was done" section carrying two to
  four figures lifted from the report), the case's full report (`report.html`) with the figures it
  references beside it, and `files/` with the working folder mirrored (raw downloads and files over
  2 MB are left out; `files/index.html` lists them and points here). `site/cases.json` holds the
  scoreboard as data.
- `cases/<slug>/` is each case's complete working folder: report, README, notes and dossiers, code,
  data and downloaded sources. Start with the README in each folder.
- `content/cases.py` is the text of the headline page and the case pages; every verdict, confidence
  and "what is new" item is taken from the case's own report and README, and the evidence label is
  set from what the report discloses about its evidence.
- `templates/site.css` is the site's stylesheet; `templates/thumbs/` holds a small image of one figure
  from each case, shown in the cover table; `templates/mermaid/` is where a diagram drawn once from a
  report's mermaid source would go, for `build.py` to put in the source's place, since the site runs
  no scripts (no report needs one at present). `build.py` builds `site/`; `sync_cases.py` copies the
  working folders into `cases/`, leaving out the files listed in `sources_left_out.csv` and files over
  95 MB. A second report kept in a case folder
  (the Bixby letter's independent rerun) is served under the case as `rerun/`.
- `netlify.toml` publishes `site/` with no build step.

## Rebuilding

    python3 build.py            # regenerates site/ from cases/ and content/cases.py
    python3 build.py --dry-run  # lists what would be mirrored without writing

Python 3.8 or later, no dependencies. The reports' own code lives in each case folder and is
described in that folder's README.
